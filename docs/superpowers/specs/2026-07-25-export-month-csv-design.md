# Cha-Ching — Export This Month to CSV — Design Spec

**Date:** 2026-07-25
**Owner:** Eve (gamaliel)
**Status:** Approved in-session

## Problem

Settings → Export CSV can export expenses, debts, and debt payments, but not
the month plan itself. There is no way to get a month's lines — what's due,
in which cutoff, from which account, what's already ticked — out of the app for
sharing or record-keeping. Debt money is also split across two places (lines
that pay a debt, and payments logged straight from the Debt Plan screen), so
even a manual copy of the month misses part of the picture.

## Design

A fourth row in Settings → Export CSV: **`This month (2026-07)`**, labelled
with the month currently being browsed. One CSV download, seven columns.

### Which month

The row reads `useMonth()` — `Settings` renders inside `MonthProvider`, so the
export follows the month browser on the Month tab. This covers past months and
future months that haven't been started (whose `lines` are generated by
`generateMonthLines`, not stored in Firestore) without any extra fetch.

Filename: `month-<viewedKey>.csv`, e.g. `month-2026-07.csv`.

### Columns

| Column | Source |
|---|---|
| Cutoff | `line.cutoff` (1 or 2) |
| Name | `line.name` |
| Amount | `line.amount` |
| Channel | `line.channel` |
| Status | `line.status` (`PAID`, `RECEIVED`, … or blank) |
| Type | `recurring` · `one-off` · `debt-payment` |
| Pays debt | debt name resolved from `line.debtId`; blank when none |

### New module — `src/lib/monthExport.ts`

One pure function, no Firestore:

```ts
export interface MonthExportRow {
  cutoff: number; name: string; amount: number; channel: string;
  status: string; type: "recurring" | "one-off" | "debt-payment";
  paysDebt: string;
}

export function monthExportRows(
  lines: readonly MonthLine[],
  payments: readonly PaymentRec[],
  debts: readonly Debt[],
  monthKey: string,
): MonthExportRow[];
```

- Each month line becomes a row. `type` is `one-off` when `line.oneOff`,
  otherwise `recurring`.
- `paysDebt` looks up `line.debtId` in `debts` and uses the debt's `name`;
  blank when the line pays no debt **and** when the referenced debt no longer
  exists (no throw — matches the app's existing tolerance for deleted debts).
- Standalone debt payments are appended: `payments` where
  `p.monthKey === monthKey` **and `p.lineId` is absent**. These are the
  target/spill/minimum payments logged from the Debt Plan screen. Payments that
  carry a `lineId` were created by ticking a month line PAID
  (`toggleLinePaid` in `repo.ts`), and that line is already a row — including
  them would double-count the same peso.
- A standalone payment row is: `name` = `Extra payment`, `amount` = `p.amount`,
  `channel` = the debt's `channel` (blank if the debt was deleted),
  `status` = `PAID`, `type` = `debt-payment`, `paysDebt` = the debt's name
  (`Unknown debt` if deleted — the payment is real even when the debt record
  isn't), `cutoff` = `p.cutoff`.
- Ordering: cutoff ascending; within a cutoff, lines first (sorted by
  `lineComparators.order` from `src/lib/lineSort.ts`), then debt-payment rows
  in the order given.

### Wiring

- `src/components/settings/ExportData.tsx` — add the row. Lines come from
  `useMonth().lines`; `debts` and `payments` are already fetched there. Emits
  via the existing `toCsv` / `downloadCsv` helpers, so names containing commas
  or quotes are escaped by code that already has test coverage.
- `src/components/DebtPlan.tsx` — add `lineId?: string` to `PaymentRec`. The
  field is written today by `repo.ts` but not declared on the interface.

## Error handling

- A month with no lines exports a header-only CSV rather than failing.
- Deleted debts degrade to blank / `Unknown debt` as above; no lookup throws.
- Projected months (no Firestore doc) have no payments, so the file is
  lines-only. That is correct — nothing has been paid yet.

## Testing

New `src/lib/monthExport.test.ts` (vitest, alongside the other `src/lib`
tests):

1. line → row mapping, all seven columns
2. `oneOff` line typed `one-off`
3. `debtId` resolves to the debt's name in `Pays debt`
4. line whose `debtId` points at a deleted debt → blank `Pays debt`
5. payment carrying `lineId` is excluded (no double count)
6. payment without `lineId` is included as a `debt-payment` row
7. payment from a different `monthKey` is excluded
8. ordering — cutoff ascending, lines before debt-payment rows within a cutoff

Plus `npm run typecheck`, full `npx vitest run`, `npm run build`, and a manual
check: export the current month, open in Sheets, confirm a ticked debt line
appears once and a Debt Plan extra payment appears as its own row.

## Out of scope

- Income rows and TOTAL IN / TOTAL OUT rows (explicitly declined).
- Debt balance / minimum summary block (declined).
- Exporting the recurring template blueprint separately.
- Re-importing a CSV.
